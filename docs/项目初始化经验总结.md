# 项目初始化经验总结

> 本文记录 RAG_demo（企业合规智能平台）从零初始化到「可运行骨架」的完整过程、关键命令与踩坑经验，
> 供后续同类项目（Vue3 + FastAPI + Dify 架构）参考复用。

## 1. 背景与目标

- **技术栈**：Vue 3 + Vite + TypeScript + Element Plus + Pinia + Vue Router 4（前端）；Python 3.11+ FastAPI（后端）；Dify（AI 编排）。
- **本次目标**：初始化 git 仓库、忽略参考代码目录、搭好前后端可运行骨架并装好依赖、通过验证。

## 2. Git 仓库初始化

```bash
cd RAG_demo
git init
```

### .gitignore 要点

- **带空格的目录名要写全路径**：`Reference code` 目录忽略写成 `/Reference code/`，而不是 `Reference code/` 的歧义写法。
- **两层忽略**：根目录一份（覆盖 Python/Node/系统文件），前端脚手架还会自带一份 `frontend/.gitignore`（覆盖 `node_modules/`、`dist/`），两份叠加生效。
- **`.env` 忽略、`.env.example` 保留**：这是密钥管理的核心约定，用 `!.env.example` 反转忽略。
- 常见忽略项：`.venv/`、`__pycache__/`、`*.py[cod]`、`node_modules/`、`dist/`、`.DS_Store`、`.idea/`、`.vscode/`（但保留 `extensions.json`）。

验证忽略是否生效：`git check-ignore <path>`，输出路径即表示已忽略；无输出表示会被跟踪。

## 3. 前端初始化（脚手架）

```bash
npm create vite@latest frontend -- --template vue-ts
cd frontend
npm install                                        # 基础依赖（vue 等）
npm install element-plus pinia vue-router axios markdown-it highlight.js
npm install -D @types/markdown-it
```

### 目录结构（遵循项目规范）

```
frontend/src/
├── api/          # axios 封装(http.ts) + 按模块：chat/knowledge/generate
├── views/        # 页面：ChatView/KnowledgeView/ReviewView/GenerateView/TemplateView/CorrectView
├── components/   # 通用组件
├── stores/       # Pinia（user.ts）
├── router/       # Vue Router
└── main.ts       # 注册 Element Plus + Pinia + Router
```

### 关键配置

1. **路径别名 `@` 需两处同步**：
   - `vite.config.ts`：`resolve.alias` 指向 `src`。
   - `tsconfig.app.json`：`compilerOptions.paths` 配 `"@/*": ["./src/*"]`。
   - 两处不一致会导致「打包能用、IDE 类型报错」或反之。

2. **Element Plus 全量引入 + 中文语言包**：
   ```ts
   import ElementPlus from 'element-plus'
   import 'element-plus/dist/index.css'
   import zhCn from 'element-plus/es/locale/lang/zh-cn'
   app.use(ElementPlus, { locale: zhCn })
   ```

3. **SSE 流式对话用 fetch 而非 axios**：axios 默认不支持流式读取，用 `fetch` + `ReadableStream` + `TextDecoder` 按 `\n\n` 切分 SSE 事件。

4. **开发期跨域用 Vite 代理**：`/api` 代理到 `http://127.0.0.1:8000`，避免后端配 CORS 的复杂度（生产仍建议 Nginx 转发）。

## 4. 后端初始化（FastAPI 分层骨架）

后端无官方脚手架，手动按项目规范分层：

```
backend/
├── app/
│   ├── api/          # 路由层：只做参数校验、鉴权依赖、转发 service
│   ├── services/     # 业务层：dify.py（核心）、document_parser.py、word_generator.py
│   ├── models/       # SQLAlchemy ORM（base.py + 每实体一个文件）
│   ├── schemas/      # Pydantic 请求/响应模型（与 models 分离）
│   ├── core/         # config.py、security.py(JWT)、deps.py、exceptions.py、constants.py
│   └── main.py       # 应用入口
├── requirements.txt
├── .env.example
└── README.md
```

### Dify 调用封装（重点）

统一封装在 `services/dify.py`，对外暴露业务方法（`chat`、`chat_stream`、`run_workflow`、`run_workflow_stream`、`upload_document` 等），
内部用 `httpx` 直接打 Dify HTTP API 并用 `aiter_lines()` 解析 SSE，**不把 Dify 当纯向量库自建检索链路**。

> 参考项目 `Reference code/cosmetics-ai/backend/app/services/dify.py` 用的就是 `httpx` 封装模式（而非 dify-client SDK），本项目沿用了这一更可控的做法。

### 统一约定

- 统一前缀 `/api/v1/`，统一响应 `{ code, message, data }`（`code=0` 成功）。
- 流式接口：后端用 `sse-starlette` 的 `EventSourceResponse`，把 Dify 的 `message`/`message_end`/`error` 事件转成 SSE。
- 鉴权：JWT（`Authorization: Bearer <token>`），通过 `core/deps.py` 依赖注入。
- 敏感密钥只存 `.env`。

## 5. 后端虚拟环境与依赖

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

`requirements.txt` 覆盖：`fastapi`、`uvicorn[standard]`、`sqlalchemy`、`pydantic-settings`、`sse-starlette`、`httpx`、`PyJWT`、`python-docx`、`docxtpl`、`dify-client` 等；`unstructured`/`pymupdf` 按需启用（注释保留）。

## 6. 验证方式

```bash
# 前端：类型检查 + 打包
npm run build

# 后端：import 检查 + 路由/健康检查（不依赖真实 Dify）

```

## 7. 踩坑记录（重要）

| 坑 | 现象 | 解决 |
| --- | --- | --- |
| **TypeScript 6.0 弃用 `baseUrl`** | `vue-tsc` 报 `TS5101: Option 'baseUrl' is deprecated` | 删掉 `baseUrl`，`paths` 无需 baseUrl 也能相对 tsconfig 解析 |
| **FastAPI 0.141 `include_router` 懒加载** | `len(app.routes)` 只有 5，误以为路由没挂上 | 这是新版懒加载表现，用 `TestClient` 或 `app.openapi()['paths']` 验证，路由实际正常 |
| **网络慢导致安装极慢** | npm 基础依赖 6 分钟、全量约 11 分钟；pip 也有大包（如 lxml 8.6MB）低速下载 | 建议配置国内镜像（npm 用 npmmirror，pip 用 `-i` 清华/阿里源）加速 |
| **Python 3.14 兼容** | 项目要求 3.11+，本机 3.14 | 各二进制包（lxml、httptools、uvloop 等）已发布 cp314 wheel，能正常安装；但若遇无预编译 wheel 的包需本地编译，建议团队统一 Python 3.11/3.12 |
| **`@` 别名只配一处** | 打包与类型检查结果不一致 | vite 与 tsconfig 两处必须同步配 `@/*` |
| **axios 无法流式读取 SSE** | 前端收不到流式输出 | 用原生 `fetch` + `ReadableStream` 实现 SSE 读取 |

## 8. 后续建议

1. **统一 Python 版本**：建议团队锁 3.11 或 3.12（用 `.python-version` 或文档约定），避免 3.14 边缘兼容问题。
2. **数据库迁移**：骨架用 `Base.metadata.create_all` 建表，生产应切换 Alembic。
3. **权限落地**：`core/deps.py` 中 `require_admin` 目前是占位，需接入真实 RBAC 角色校验。
4. **前端按需引入**：Element Plus 全量引入导致 chunk 约 1MB，可改按需引入或 `unplugin-vue-components` 自动导入。
5. **补真实 Dify 配置**：在 `backend/.env` 填写 `DIFY_BASE_URL`、`DIFY_API_KEY` 及各业务应用 Key 后即可联调。
6. **docker-compose**：按项目规范补充前端 + 后端 + Dify + 基础设施的编排，服务间走内网容器名。
