# 冒烟测试输入（按功能模块）

> 来源：`dify/scripts/smoke_test.py`。四个模块的输入内容与判定条件集中记录在此，便于回归时核对与替换。
> 实测输出见同目录 `冒烟测试结果.md`。

## 1. 合同审查（Workflow · 需求②）

| 项 | 内容 |
| --- | --- |
| Dify 应用 | 合同审查（`DIFY_CONTRACT_REVIEW_APP_KEY`） |
| 接口 | `POST /v1/workflows/run`（`response_mode=blocking`） |
| 输入变量 | `chunk_text` |

输入内容：

```
第三条 因履行合同造成对方人身伤害的，本公司不承担任何赔偿责任。
第四条 乙方交付的钢材质量以甲方现场验收为准，甲方有权单方决定是否合格。
```

判定条件：HTTP 200 且 `is_compliant = "false"` 且 `risks` 非空。

（该文本故意包含两处典型违规：免除人身伤害赔偿责任的免责条款、排除对方质量异议权的单方验收条款。）

## 2. 制度审查（Workflow · 需求③）

| 项 | 内容 |
| --- | --- |
| Dify 应用 | 制度审查（`DIFY_REGULATION_REVIEW_APP_KEY`） |
| 接口 | `POST /v1/workflows/run`（`response_mode=blocking`） |
| 输入变量 | `chunk_text` |

输入内容：

```
第五条 员工出差住宿费实行实报实销，不设上限，无需部门负责人审批。
第六条 采购金额在50万元以下的，可由采购员自行确定供应商并签订合同，无需招标。
```

判定条件：HTTP 200 且 `is_compliant = "false"` 且 `risks` 非空。

（该文本故意与现行制度/上位法冲突：费用支出失去审批监督、小额采购规避招标程序。）

## 3. 合规咨询（Chatflow · 需求④）

| 项 | 内容 |
| --- | --- |
| Dify 应用 | 合规咨询（`DIFY_CHAT_APP_KEY`） |
| 接口 | `POST /v1/chat-messages`（`response_mode=blocking`） |
| 输入变量 | `category` = `差旅` |
| 用户提问 | `差旅住宿标准是多少？` |
| 其他参数 | `conversation_id` = 空（新建会话） |

判定条件：HTTP 200 且回答长度 > 20 字 且 `metadata.retriever_resources` 非空（必须有引用来源）。

## 4. 规章制度生成（Workflow · 需求⑧，outline 模式）

| 项 | 内容 |
| --- | --- |
| Dify 应用 | 规章制度生成（`DIFY_GENERATE_APP_KEY`） |
| 接口 | `POST /v1/workflows/run`（`response_mode=blocking`） |
| 输入变量 | `requirement`、`mode` |

输入内容：

```
requirement: 制定一份钢材采购管理办法，明确采购申请、供应商选择、合同签订与验收付款流程
mode: outline
```

判定条件：HTTP 200 且 `outline_text` 长度 > 100 字 且 `sections_json` 为空（大纲模式不返回章节 JSON）。

---

## 说明

- 四个模块均使用 `user = "smoke"` 作为调用标识。
- 输入内容是有意设计的「最小可判定样本」：用最短文本触发确定性的判定路径（违规/冲突/需引用/需大纲），避免长文档带来的耗时与不确定性。
- 端到端（含分块、进度、合并）的输入请用真实文件，见 `backend/README.md` 的审查服务说明。
